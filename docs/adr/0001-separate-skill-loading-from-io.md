# Separate skill loading from I/O

The Skills capability discovers Agent Skills and reveals their instructions and filesystem location through Pydantic AI's deferred-capability mechanism. It does not provide file-reading or script-execution tools: applications grant those permissions explicitly by composing Skills with filesystem, shell, or execution-environment capabilities. By default, a resource-bearing skill validates that a first-party `FileSystem` capability contains the skill directory when the skill is activated. A tool with the same name is not treated as filesystem authority. Explicit custom reader and executor names are caller declarations because wrappers may change how tools are presented to the model. Wrappers such as CodeMode own that presentation; Skills only describes the operation and authorized path. Script execution remains optional and is described accurately to the model. This avoids making skill discovery an implicit code-execution boundary and reuses the existing I/O controls in Harness.
